# ANPR-Gate

Приложение для контроля проезда по российскому номеру, цвету и кузову автомобиля.
Принимает видеофайл или RTSP, распознаёт номер, находит ТС в SQLite и показывает
оператору решение: **ПРОПУСТИТЬ**, **ПРОВЕРКА ОПЕРАТОРОМ** или **ОТКАЗ**.

Кузов сравнивается с эталоном именно той записи, чей номер прочитан. Ручное
решение оператора сохраняется в журнал; управления реле или шлагбаумом в этом
проекте пока нет.

## Что нужно для запуска

- Windows или Linux с графической сессией для GUI; для headless окно не требуется.
- Python **3.11 или 3.12, 64-bit**. Установщик проверяет версию и не использует
  Python 3.13+ для закреплённой пары PyTorch 2.5.1 / torchvision 0.20.1.
- Основные веса моделей входят в репозиторий и приходят с обычным `git clone`.
- NVIDIA необязательна: доступен запуск на CPU.

**Git LFS не используется.** В репозитории находятся исходники, тесты, инструкции,
пример конфигурации, манифест и три веса основного режима `ru_anpr + shape`.
После клонирования переносить модели вручную не нужно. Запасной FastReID
автоматически загружается из Releases при выборе этого backend и проверяется
по SHA256. Видео, рабочие базы, снимки, история камер и окружение остаются локальными.

## Быстрый старт на Windows

Откройте PowerShell в корне проекта:

```powershell
py -0p
powershell -ExecutionPolicy Bypass -File .\SETUP.ps1
.\.venv\Scripts\python.exe scripts\check_assets.py
.\.venv\Scripts\python.exe -m anprgate ui
```

Установщик создаёт `.venv`, устанавливает зависимости, проверяет их и создаёт
пустую базу. Он также проверяет модели и подготавливает выбранный backend.
При первой установке он копирует `anpr.example.yaml` в локальный
`anpr.yaml`; существующую конфигурацию сохраняет. При ошибке установка
останавливается с ненулевым кодом завершения.

Устройство выбирается автоматически: рабочая NVIDIA через `nvidia-smi` — CUDA
12.1, иначе CPU. CUDA-сборка PyTorch 2.5.1 использует cuDNN 9, совместимый
с ONNX Runtime 1.22.0. Выбор можно задать явно:

```powershell
powershell -ExecutionPolicy Bypass -File .\SETUP.ps1 -Device cpu
# Или сборка CUDA 12.1:
powershell -ExecutionPolicy Bypass -File .\SETUP.ps1 -Device cu121
```

Если нужен определённый интерпретатор:

```powershell
powershell -ExecutionPolicy Bypass -File .\SETUP.ps1 -Python 'C:\Python312\python.exe' -Device cpu
```

Для обычного запуска без консоли используйте `START.bat`. Для диагностики
запускайте `python.exe -m anprgate ui`, чтобы видеть ошибки. При запуске через
`pythonw` сообщения logging сохраняются в `data/anprgate.log`.

`START_cam1.bat`, `START_cam2.bat`, `START_both.bat` и `START_gui.bat` открывают
одно и то же окно. Одно окно обрабатывает один выбранный источник.

## Быстрый старт на Linux

Из корня проекта проверьте интерпретатор:

```bash
python3 --version
```

На Ubuntu 24.04 системный Python 3.12 подходит. В системах с apt установите
окружение и библиотеки окна:

```bash
sudo apt update
sudo apt install python3-venv python3-pip libgl1 libglib2.0-0 libxcb-cursor0
bash setup.sh
.venv/bin/python scripts/check_assets.py
.venv/bin/python -m anprgate ui
```

Сообщение о замене `libglib2.0-0` на `libglib2.0-0t64` нормально. Если системный
Python версии 3.13 или новее, сначала установите 3.11/3.12 способом, подходящим
для вашего дистрибутива. Не все дистрибутивы имеют пакет `python3.11` в штатных
репозиториях.

Можно выбрать устройство и интерпретатор:

```bash
bash setup.sh --device cpu
ANPR_PYTHON=python3.12 bash setup.sh --device cu121
```

После установки окно открывается также через `bash start.sh`. При SSH без
графической сессии используйте headless-команду ниже. RTSP читается PyAV;
аппаратный путь D3D11VA реализован только для Windows, Linux использует CPU
декодирование.

Для выхода из активированного виртуального окружения выполните `deactivate`.
Активация необязательна, если указывать путь к `.venv/bin/python` или
`.venv\Scripts\python.exe` явно.

Если установка старой версии завершилась конфликтом `torch 2.2.2` и
`nvidia-cudnn-cu12`, обновите репозиторий и повторите `bash setup.sh`.
Скрипт обновит PyTorch и torchvision внутри существующего `.venv`; удалять
окружение, конфигурацию и базу не нужно. Проверка после установки:

```bash
.venv/bin/python -m pip check
.venv/bin/python scripts/env_check.py
```

## Проверка на видеофайле

На Windows:

```powershell
.\.venv\Scripts\python.exe -m anprgate headless --source 'D:\Videos\entry.mp4' --max-frames 120
```

На Linux:

```bash
.venv/bin/python -m anprgate headless --source /home/user/Videos/entry.mp4 --max-frames 120
```

Замените путь на свой ролик. В исходной локальной поставке для проверки есть
`data/videos/gemini_b.mp4`. Без `--max-frames` обрабатывается весь файл;
`--realtime` ограничивает темп исходной скоростью видео.

По умолчанию выбран `ru_anpr` — OCR российских номеров. Для роликов с иностранными
номерами, например `ParkingVideo.mp4`, можно выбрать универсальный `fast_alpr`
только на время запуска, не меняя `anpr.yaml`:

```bash
.venv/bin/python -m anprgate -v ui --plate-backend fast_alpr --source /home/user/Videos/ParkingVideo.mp4
```

Параметр `--plate-backend` доступен также для `headless`. При первом использовании
FastALPR его ONNX-модели скачиваются автоматически; нужен доступ к GitHub.
Для номеров РФ оставьте стандартный `ru_anpr`. Выбор OCR не меняет правила допуска.

Если ТС обнаружено, но уверенного прочтения номера нет, при завершении трека
или ролика в журнал записывается **«ОТКАЗ — номер не распознан»** со снимком ТС.
Подпись `номер…` во время видео означает, что чтение ещё не получено.

Новая база пустая, поэтому распознанные номера получают отказ «номер отсутствует
в базе». После добавления номера без эталона кузова при стандартной конфигурации
ожидается проверка оператором. Это результат правил доступа, а не ошибка запуска.

## Конфигурация и RTSP

`anpr.example.yaml` — общий образец в Git. `anpr.yaml` — локальные настройки,
которые Git игнорирует. Без локального файла приложение читает образец.
При необходимости создайте копию вручную:

```powershell
Copy-Item anpr.example.yaml anpr.yaml
```

На Linux: `cp anpr.example.yaml anpr.yaml`. Относительные пути к видео, весам,
БД и снимкам считаются от папки выбранного конфига. Общий параметр `--config`
ставится перед командой:

```powershell
.\.venv\Scripts\python.exe -m anprgate --config anpr.yaml ui
```

Приоритет источника: `--source`, затем `ANPR_SOURCE`, затем `source.uri`.
Для камеры удобнее кнопка **«Камера (RTSP)…»**. В командной строке Windows:

```powershell
$env:ANPR_SOURCE = 'rtsp://USER:PASSWORD@HOST:554/streaming/Channels/101'
.\.venv\Scripts\python.exe -m anprgate ui
Remove-Item Env:ANPR_SOURCE
```

На Linux:

```bash
ANPR_SOURCE='rtsp://USER:PASSWORD@HOST:554/streaming/Channels/101' .venv/bin/python -m anprgate ui
```

USER, PASSWORD, HOST и путь замените параметрами своей камеры. Уже закодированные
логин/пароль сохраняются с одним уровнем percent encoding. Пароль маскируется
в отображаемом источнике и журнале. Для символов `/`, `?`, `#` в авторизации
используйте percent encoding, поскольку они разделяют части URL.

История подключений в `data/recents.json` содержит исходные адреса с учётными
данными для повторного подключения. Храните её локально. Переменные окружения
запуска также могут содержать учётные данные; не добавляйте их в общие скрипты.

Основные параметры приёма:

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `ANPR_RTSP_TRANSPORT` | TCP или UDP | `tcp` |
| `ANPR_RTSP_OPEN_TIMEOUT_MS` | Таймаут открытия | `8000` |
| `ANPR_RTSP_RECONNECT_SEC` | Пауза переподключения | `2` |
| `ANPR_HW_ACCEL` | `auto` или `off` | `auto` |

Если аппаратное декодирование на Windows даёт сбой, задайте
`$env:ANPR_HW_ACCEL = 'off'` перед запуском.

## Справочник и журнал

Команды ниже для Windows; на Linux замените путь к интерпретатору на
`.venv/bin/python`:

```powershell
.\.venv\Scripts\python.exe -m anprgate db add А123ВС77 --color белый --owner 'Иванов'
.\.venv\Scripts\python.exe -m anprgate db list
.\.venv\Scripts\python.exe -m anprgate db colors
.\.venv\Scripts\python.exe -m anprgate db import data\vehicles_example.csv
.\.venv\Scripts\python.exe -m anprgate events --limit 20
```

Латиница `A123BC77` приводится к `А123ВС77`. CSV имеет заголовки
`plate,color,owner,note`, разделитель-запятую и кодировку UTF-8. При импорте
существующая запись с тем же номером обновляется. Цвет обязателен для записи,
даже если его проверка отключена.

В GUI справочник открывается кнопкой **«Справочник ТС…»**. Можно добавлять,
изменять и удалять записи, а также отключать пропуск.

Просмотр ролика пополняет журнал проездов. В справочник ТС автомобили добавляются
оператором: через «Справочник ТС…» или кнопку «Добавить в базу…» в карточке события.

Рабочая база находится в `data/anpr.sqlite3`, снимки — в `data/snapshots/`.
Для резервной копии завершите приложение и сохраните БД вместе с необходимыми
снимками отдельно от Git. Действия оператора записываются отдельно от исходного
автоматического решения.

## Как создать эталон кузова

1. Добавьте правильный номер автомобиля в справочник.
2. Откройте ролик или подключите камеру и дождитесь карточки этого ТС.
3. Проверьте номер, найденную запись и изображение машины.
4. Нажмите **«Сохранить эталон кузова»** и дождитесь сообщения в заголовке карточки.
5. Повторите обработку источника или дождитесь следующего проезда.

Сохранение выполняется фоновым работником через выбранную модель и с маской
номера. Кнопка заменяет прежнюю галерею этой записи одним эталоном. При ошибке
сохранения предыдущий эталон остаётся на месте. После смены backend или формулы
признака пересоздайте галереи.

Для стандартного `shape` отдельная нейросеть кузова не нужна. При выборе `fastreid`
стандартные дополнительные веса автоматически скачиваются при установке или
первой загрузке этого backend. Их можно подготовить заранее командой
`.venv/bin/python scripts/fetch_models.py --all` (на Windows — через
`.venv\Scripts\python.exe`). Подробности геометрического
признака, маски номера и формата BDY1 — в [описании кузова](docs/body_descriptor.md).

Скрипт `scripts/body_separation_check.py` предназначен для демонстрационных
роликов исходной поставки. Без `--write` он только печатает сравнения.
Для записи галерей используйте явные номера демонстрационных автомобилей
по инструкции `python scripts/body_separation_check.py --help`; рабочую базу
произвольно выбранными записями он не заполняет.

## Как принимается решение

В общем образце выбран OCR `ru_anpr`, кузов `shape`, цвет отключён для ночного
режима. Номер проверяется первым, затем цвет и кузов найденной записи.

| Условие | Результат |
|---|---|
| Номер не распознан | Отказ с записью в журнал при завершении трека или ролика |
| Номер отсутствует в базе или пропуск выключен | Отказ |
| Нечёткое совпадение номера | Проверка оператором |
| Недостаточно согласованных прочтений или доля ниже `consensus` | Положительный результат переводится в проверку |
| Кузов ниже `body_alarm` | Отказ |
| Кузов между `body_alarm` и `body_match`, цвет отключён | Проверка оператором |
| Нет эталона при выключенном цвете либо ошибка сверки | Проверка оператором |
| Номер и включённые проверки подтверждены | Пропустить |

Отказ по одному признаку сохраняется независимо от успешности других проверок.
Требование согласия OCR применяется и при `max_votes`, и при потере трека,
и в конце файла. Повреждённый эталон не останавливает обработку источника.

Ключевые настройки:

| Параметр | Смысл |
|---|---|
| `processing.frame_interval` | Обрабатывать каждый N-й кадр |
| `processing.min_votes`, `consensus` | Минимум голосов и доля за номер |
| `processing.max_votes` | Предел ожидания перед финализацией |
| `processing.repeat_cooldown_sec` | Подавление повторных событий по номеру |
| `processing.max_frame_side` | Максимальная сторона обрабатываемого кадра |
| `access.body_match`, `body_alarm` | Пороги совпадения и отказа по кузову |
| `access.color_check` | Учитывать ли цвет |
| `access.color_unknown_decision` | Решение при недостоверном цвете |

Рамки на видео возвращаются в координатах исходного изображения, включая 4K.
При закрытии окно ждёт окончания работника и затем закрывает БД. Загрузку
модели или текущий инференс прервать мгновенно нельзя; статус показывает
завершение обработки.

## Проверки и диагностика

```powershell
.\.venv\Scripts\python.exe -m pytest tests -q
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe scripts\check_assets.py
.\.venv\Scripts\python.exe -m anprgate -v ui
```

Тесты используют временные базы, подставные модели и Qt offscreen. Камеру и
скачивание моделей они не запускают. Проверки эталонов используют манифест
файлов; `--all` требует также необязательный FastReID. Для его предварительной
загрузки используйте `scripts/fetch_models.py --all`.

| Симптом | Действие |
|---|---|
| `Unable to locate package python3.11` | Проверьте `python3 --version`; на Ubuntu 24.04 используйте 3.12 и `python3-venv` |
| Не найдено окружение | Запустите установщик из корня проекта |
| Нет весов OCR | Выполните `git restore -- weights` и `check_assets.py` |
| Все номера получают отказ | Проверьте `db list`: новая база пустая |
| Видны рамки ТС, но написано `номер…` | Проверьте тип номеров: для иностранных используйте `--plate-backend fast_alpr`; дождитесь конца трека или ролика для записи непрочитанного номера |
| Известный номер получает проверку | Прочитайте причины; проверьте эталон и согласие OCR |
| Окно не запускается через BAT | Запустите `python.exe -m anprgate ui` из консоли |
| Нет графического дисплея | Используйте headless или графическую сессию |
| После смены модели не работает эталон | Пересоздайте галерею этой записи |

## Работа с Git без LFS

В Git попадают исходники, тесты, документация, общий конфиг, манифест и три
основные модели из `weights/`. Локальные настройки, камеры, БД, снимки,
остальные модели, видео и окружения исключены.
Исходные файлы на диске остаются на месте.

Для нового каталога репозитория:

```bash
git init -b main
git add .
git status --short
git diff --cached --stat
```

Проверка подготовленного индекса и установка pre-commit hook:

```powershell
.\.venv\Scripts\python.exe scripts\check_repository.py
.\.venv\Scripts\python.exe scripts\check_repository.py --install-hook
```

На Linux используйте `.venv/bin/python`. Проверка читает именно staged-файлы
и проверяет три разрешённые модели по размеру и SHA256 из staged-манифеста.
Для них действует предел GitHub 100 MiB; для остальных файлов — 5 MiB.
Проверка блокирует локальные данные, остальные бинарные assets, LFS-указатели,
приватные ключи и RTSP-авторизацию вне тестовых примеров. Это защита от типовых
ошибок подготовки коммита; содержимое новых файлов всё равно нужно просматривать.
Установщик hook сохраняет чужой существующий pre-commit и предлагает добавить
проверку вручную.

После просмотра подготовленных файлов:

```bash
git commit -m "fix: harden recognition decisions and prepare source repository"
```

Удалённый репозиторий и `git push` настраиваются отдельно. Перед первым push
не инициализируйте серверный репозиторий отдельным README, если хотите
отправить эту локальную историю без объединения.

При внешнем распространении учитывайте лицензии всех зависимостей и права
