# Target design: access-decision

Что не меняется: порядок этапов (номер → цвет → кузов), SQLite-схема, маска RTSP, пороги `body_match` 0.75 и `body_alarm` 0.45, ночной `color_check: false` в `anpr.yaml`, модели OCR.

Что меняется на месте, без переписывания конвейера:

1. `_check_plate` всегда эскалирует нечёткость в `review`.
2. `_check_body` не присваивает `ALLOW` и не фильтрует причины цвета.
3. `_body_match` отличает «нет эталона» (нет записи или нет вектора) от «сверка не выполнена» (нет сети, исключение, чужая размерность).
4. Сбойная причина попадает в `reasons`, потому что таблица `events` этапы не хранит.

Порядок уже выполнен для G-001, G-002, G-003. Дальше, отдельными заходами: G-004, G-005, G-006. G-008 не чинится кодом.

Откат правки: вернуть три функции. Схема базы не менялась, миграции нет.
