# Reconstructed spec: decide()

Это поведение кода, не требование бизнеса. Требование поста записано отдельно в `acceptance-brief.md`.

## Инварианты, которые код держал до правки

- Нет номера или номера нет в базе или пропуск выключен → `deny`.
- Точное совпадение, цвет совпал (или проверка цвета выключена) и кузов не возразил → `allow`.
- Нечёткость следует полю `fuzzy_decision`.
- Цвет не определён → `color_unknown_decision`.
- Кузов ≥ `body_match` мог снять цветовой `deny`.

## Инварианты после правки G-001…G-003

- Неизвестный и нечитанный номер → `deny`.
- Любое ненулевое расстояние Левенштейна в пределах `fuzzy_max_distance` → `review`, поля `fuzzy_decision` исход не меняют.
- Цветовой `deny` не становится `allow` из-за близости кузова. Причина цвета остаётся в `reasons`.
- Причина, содержащая «не выполнена», поднимает решение минимум до `review` и пишется в `reasons`.
- «Нет эталона» при включённом цвете по-прежнему этап `skip` (G-004, открыто).

## Требования (как код отвечает сейчас)

- WHEN номер пустой THEN `deny`, этапы цвета и кузова `skip`.
- WHEN номер не найден или пропуск выключен THEN `deny`.
- WHEN расстояние 1..`fuzzy_max_distance` и кандидат один THEN `review`.
- WHEN два кандидата на одном расстоянии THEN совпадения нет (`find_vehicle` → `None`).
- WHEN цвет не совпал ни по имени, ни по ΔE THEN `deny`, даже если кузов ≥ `body_match`.
- WHEN сверка бросила исключение, сеть не загружена или вектор чужой длины THEN причина «сверка кузова не выполнена» и не `allow`.
- WHEN оператор жмёт кнопку THEN меняется только `events.operator_action`, не `events.decision`.
